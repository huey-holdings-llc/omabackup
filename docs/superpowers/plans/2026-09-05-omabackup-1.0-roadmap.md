# OmaBackup after 0.7.0: what is left for 1.0

0.7.0 ships everything the five-lens expert review put above the cut line, plus
everything the three fix rounds on top of it found. This file is the remainder:
the items the review itself marked "later", the minors nobody blocked on, and
the follow-ups the wave reviews deferred while fixing something next to them.
Each is real, each is survivable in a first public release, and each is better
as its own pull request with its own review than folded into a release branch.

One line each, with the lens or the round that raised it. Row numbers refer to
the deduplicated table in the review synthesis; the per-lens reports carry the
evidence and a fix sketch for every one.

worth knowing before trusting a red run of it.

## Deferred by the review (rows marked "later")

- **Row 12, one cleanup registry (architecture C2, security M7).** `lib/drift.sh`
  and `lib/verify.sh` each install a bare `EXIT` trap, so whichever runs second
  silently replaces the first one's cleanup; the current ordering is what keeps
  it harmless, and the ordering is undocumented.
- **Row 23, one reply layer (architecture I1, I2, I3).** The triage verbs print
  JSON whether or not `--json` was passed, `problems[]` is an array of strings in
  three places and of objects in `lint`, and a `status` run against a broken repo
  leaves the old status.json in place instead of writing a degraded one.
- **Row 30, an inconclusive probe that never ends (future proofing I7).**
  Unauthenticated GitHub API calls are rate limited per IP, so behind CGNAT or an
  office NAT the probe can answer 403 for weeks; the push stops, correctly, and
  nothing distinguishes "probed private today" from "have not been able to ask
  since August".
- **Row 31, the allowlist floor of 20 (future proofing I9).** A user who trims
  the seed list to the fifteen paths their machine actually has is refused with a
  message phrased as damage detection; the floor should be
  `min(20, entries at the last successful run)` and should name its own escape
  hatch.
- **Row 33, `setup check` as a doctor (usability I2, documentation 6).** It
  prints a flat `key: value` dump and names a package for gitleaks alone. The
  README no longer promises otherwise, so only the code half is left: one line
  per check with the command that fixes it.
- **Row 35, the rest of refusal recovery (usability I8, I9, I12, I13).** 0.7.0
  added a Troubleshooting row for every refusal these waves introduced, but
  `--help` on an individual verb is still a usage error, `setup --remove` without
  gum still dies "cancelled" without naming `--yes`, and the divergence
  notification still asks a non-developer to `pull --rebase`.
- **Row 40, status.json has no schema version (architecture I9).** Several of
  its two dozen fields have no reader, every read in QML is defensive, and a
  renamed field therefore reads as zero drift rather than as an error. The Wave C
  fix round deferred this explicitly while adding `dir` and `optional`, two
  fields whose meaning depends on a row's `type`, which is exactly the shape a
  schema version exists to make safe.
- **Row 41, the structural cleanups (architecture I5, I10 to I14).** The setup
  phase rank table with one live comparison, the verb list written out in three
  places, three functions living in the wrong file, `lib/verify.sh` owning
  restore's globals, config merging in three different shapes, and `Panel.qml`
  re-deriving service state the service already knows.

## Raised by the wave reviews and fix rounds

- **A random suffix for the suite's `$ROOT`, and a lint symlink scan scoped to
  the shipped tree (Round 2, the flaky group 15).** Clearing `tests/tmp` while a
  run is in flight deletes that run's own fixture root. The fix is not to do
  that, but both changes would make it impossible to do by accident.
- **The `/etc` scan still parses pacman prose line by line (Round 2, R6
  deviation 2).** Every other reader in `lib/` is NUL-delimited now; these two
  read `pacman -Qii` and `-Qqo` output, which has no NUL form, so a newline in an
  `/etc` backup-file path still produces a fragment row. It needs a different
  producer contract: ask pacman for one field by name rather than reading its
  paragraphs.
- **Edit distance 2 is generous on short config keys (Wave B concern 3).** A
  future `timers` or `notifys` would be refused as a typo of `timer` or `notify`
  rather than warned about. It errs toward halting, which is the right direction,
  but it is the trade to revisit the next time a knob is added with a name close
  to an existing one.
- **Two forks per process on the hot path (Wave B concern 1, Wave A).**
  `config_load` runs `systemd-analyze` twice on every verb, including the widget's
  status refresh, and each secret scan probes `gitleaks ... --help` to choose
  between the modern and the legacy subcommand. Validate on write and cache the
  capability probe rather than dropping either check.
- **`restore_list_would` covers `--configs` only (Wave C fix round, deferred).**
  The other stages say what they would install or enable but do not name paths,
  and the helper has no fallback when jq is missing.
- **The glob-character refusal is blunt about `[` (Wave C fix round, item 6).**
  `allow` and `ignore` refuse any path containing `*`, `?` or `[`, which is right
  for the first two and heavy-handed for a file whose name simply contains a
  bracket. Escaping is the alternative, and escaping list entries correctly is
  its own small project.
- **The vanish guard writes a scratch file under `$STATE_DIR` (Round 3 concern
  2).** One `mktemp` per run that has anything missing, removed on both paths
  out, and it now dies rather than proceeding if the file cannot be created. That
  is the intended direction and it is also a new way for a full state directory to
  stop a backup.
- **`H_DRIFT_COUNT` and the snapshot's `DRIFT_N` still disagree on TOOBIG and
  EXCLUDED rows (#13).** ERROR rows are now excluded from both, but health
  counts TOOBIG and EXCLUDED while the snapshot's own count does not; one
  counter for both is the fix, and `drift_count` in `snapshot --json` is the
  field automation reads.
- **`AGENTS.md` is gitignored (#10, noticed while requesting the review).**
  The Codex GitHub App reviews from the repository it can see, so the review
  priorities and do-not-touch paths in the local file never reach it. Either
  track the file or accept that the reviews are untailored.
- **The CHANGELOG has no comparison links (documentation 22).** Keep a Changelog
  1.1.0 asks for them at the foot and the file says it follows 1.1.0; they need
  tags to point at, so they arrive with the first tagged release.
